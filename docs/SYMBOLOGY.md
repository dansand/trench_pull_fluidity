## 1. The decisions — closed 2026-08-20

D1–D4 follow directly from the manuscript; where the code diverged, the code is what
changes. D5 is the only convention that was genuinely ours to set. The evidence and
warnings are kept below because the *how* of each fix still matters during the sweep.

> Evidence for everything below: `SYMBOLOGY_EVIDENCE.md`, generated by
> `tools/manuscript_symbols.py`. Counts are **math-mode only** — rendered mathematics, not
> raw occurrences of a string in a file, and not Python identifiers.

### ✅ DECIDED 1 — `N_D` or `F_D` for the in-plane resultant?

The single biggest divergence in the project, and the counts are perfectly disjoint:

| | `N_D` | `F_D` |
|---|---|---|
| `main.tex` + `si.tex` | **44** | **0** |
| all code + slides + poster | **0** | **237** |

Not "mostly" — *zero overlap in either direction*. The manuscript defines and names it:

> "…the balance falls almost entirely on the in-plane resultant: $\Delta N_D \approx
> -\Delta\bar\sigma_{zz}$"

`N` (resultant) versus `F` (force) is a deliberate distinction in the manuscript's
register. `HOW_TO_READ.md` requires symbols be introduced by name; `trench_pull_fluidity/
CLAUDE.md` independently insists these are *resultants, not directional tractions*. The
code and the paper are saying the same physics with different letters.

**Decision (2026-08-20): `N_D` everywhere** — rendered LaTeX, labels, captions, *and*
Python identifiers (`n_d`). The manuscript uses `N_D` 44 times and `F_D` zero times
(counts above; re-verified against main.tex + si.tex directly); this was never an open choice, the
manuscript is the source of truth. The cheaper leave-Python-as-`F_D` alternative is
rejected — no standing translation layer.

### ✅ DECIDED 2 — the shear component: `τ_zx`, `τ_xz`, or `σ_xz`?

Three spellings of one component, and the index order is transposed between paper and code:

| | count |
|---|---|
| manuscript `\tau_{zx}` | 33 |
| manuscript `\tau_{zx,x}` | 45 — *a named quantity in the abstract* |
| manuscript `\tau_{xz}` | 1 |
| code `\tau_{xz}` | 30 |
| code `\sigma_{xz}` | (see §2) |

`τ_zx` and `τ_xz` are equal by symmetry, so this is pure notation — but the manuscript
chose `zx` deliberately and built `τ_zx,x` on it, which is one of the paper's three
key points. The code went the other way.

**Do not find-and-replace.** `trench_pull_fluidity/CLAUDE.md` documents
`σ_xz_zdown = −σ_xy_yup`, applied at extraction. Each occurrence sits in one of two sign
conventions and a blind rename would silently flip physics.

**Decision (2026-08-20, refined): the index order `zx` is what is binding, not the
letter.** For the off-diagonal component the deviator equals the full tensor, so
`τ_zx = σ_zx` identically; the letter is context-dependent — `τ` in the manuscript's
deviatoric register (the default), `σ` where the total-stress register is genuinely
meant (e.g. raw extraction from the model). What must follow the manuscript is the
index order: `zx`, never `xz` (`\tau_{zx}` 33× + `\tau_{zx,x}` 45×, counts above, vs.
two `xz`/`σ` strays). Renames are order-only and value-preserving (symmetric tensor) —
but each occurrence is still checked against §5 so surrounding prose does not silently
switch sign conventions.

### ✅ DECIDED 5 — the slab-frame coordinates (new; no manuscript precedent)

§12 of `fluidity_slab_normal_FD.ipynb` works in a slab-aligned frame that **the manuscript
does not contain**: `xi` (57 uses, fluidity only), `eta` (34, code only), `theta` (38,
fluidity only) against 4 / 0 / 5 in the manuscript.

So there is nothing to inherit here — the convention has to be *set* rather than synced,
and then used consistently if this work ever reaches a paper. Current usage looks
self-consistent; the decision is only whether to ratify it.

**Decision (2026-08-20): ratified as proposed** — `ξ` slab-parallel, `η` slab-normal,
`θ` local dip from the spline tangent; recorded in §5. This is the one convention that
was genuinely ours to set. Compatible with the manuscript's incidental uses: its `ξ` is
only a dummy integration variable (main.tex ~L1758) and si.tex's `θ` is likewise a local
slope/dip angle in the `N_D^{plate}` projection. Note the shelved `downdip-force-balance`
branch predates this ratification — audit it against this spec if revived.

### ✅ DECIDED 3 — `GPE*` spelling

Manuscript defines `\newcommand{\GPE}{\mathrm{GPE}^*}` and uses the macro 48 times. The
code uses the macro **zero** times — it writes the quantity longhand as `GPE*` (138),
`GPE^*` (29) and `Delta GPE` (39), with inconsistent spacing before the `*`. Needs one
plain-text spelling for Python identifiers and one LaTeX spelling for labels.

**Decision (2026-08-20): as proposed, per the manuscript's own macro** — rendered LaTeX
`\mathrm{GPE}^*` (what `\GPE` expands to), `\Delta\mathrm{GPE}^*` when it is a
difference; Python identifiers `gpe_star` / `delta_gpe_star`. No space before the `*`,
ever.

**Definitions (recorded 2026-08-20, so the sweep cannot conflate them):**
`\mathrm{GPE}` (no star) is the columnwise resultant of the *lithostatic* pressure.
`\mathrm{GPE}^*` is the columnwise resultant of the *true vertical normal stress*
($-\bar\sigma_{zz}$; the manuscript's "corrected GPE"). `\Delta` always denotes the
difference between columns. They are distinct, well-defined quantities: never star a
genuine lithostatic `GPE`, never add `\Delta` to a single-column resultant.

### ✅ DECIDED 4 — the free-surface / deflection quantity

The same physical quantity currently carries three different axis labels:

- `trench_pull_mdoodz`: `Bathymetry [m]`
- `trench_pull_fluidity`: `model free surface [m]` and `model free surface  [m]` (double space)
- `trench_pull_fluidity`: `$w$  [m]   (positive = downward deflection)`

The manuscript uses `w_T` for trench deflection (46 occurrences) and `w` generally.

**Decision (2026-08-20): as proposed, following the manuscript's `w` / `w_T`** — axis
label `$w$ [m] (positive downward)` everywhere; `w_T` for the trench deflection value;
"bathymetry" reserved for observational Earth data only.

## 4. Caption and prose conventions

Derived from `2026_version/HOW_TO_READ.md` and `POLICY_reference_values.md`.

1. **Symbols are introduced by name before first use.** "the in-plane resultant, $N_D$" —
   never a bare symbol on first appearance, in captions or in body text.
2. **Captions carry the argument alone.** `HOW_TO_READ.md` establishes that most readers
   read title → abstract → figures + captions → conclusions. A caption must state what the
   panel shows *and* the claim it supports, without requiring the body text.
3. **Caption structure:** one lead sentence naming the quantity and geometry; then panel
   letters in order; then the punchline number if there is one.
4. **Locked vocabulary** (from the manuscript's own comments and POLICY_symbols — do not
   silently substitute synonyms): *topographic pressure anomaly*, *equilibration*,
   *quantified robustness*, *normal-stress-difference resultant* (the name of $N_D$;
   "in-plane differential resultant" superseded 2026-09-01 — "differential stress" is
   reserved for principal-stress differences), *tension-like* (never bare "tension"
   except sign-convention statements and "no true tension"), *balanced* (not
   "reacted"), *strength model* (elastic properties + yield surface; "rheology" only
   for genuinely time-dependent/creep behaviour), *dynamic topography* (basal normal
   tractions from mantle/asthenosphere flow — nothing engineering-dynamic),
   *mechanical thickness*, *corrected density*, *equivalent density* (for $\hat\rho$),
   *first isostatic column* (the name of $x_I$), *maximum-moment column* (the
   name of $x_m$), *trench pull* (unhyphenated as a noun),
   *non-isostatic domain* ($x_T$ to $x_I$) and *isostatic domain* ($x_I$ to $x_R$) — the
   two additive domains of the schematic.
   **Permitted synonyms (Dan, 2026-09-21):** *trench pull domain* = non-isostatic
   domain; *ridge push domain* = isostatic domain. Both spellings are allowed and may
   be used interchangeably; the manuscript currently writes only the
   isostatic/non-isostatic pair (`framework.tex`), so these are additions, not
   replacements, and nothing needs sweeping.
   ⚠ *Ridge push domain* names the **interval**, never its content. The balance across
   it is carried by $\Delta\sigma_{zz}$, which contains the adverse asthenospheric
   pressure gradient $\Delta P$ as well as the isostatic cooling signal — "isostatic"
   refers to the topography there being compensated, not to the balance being free of
   the tilt. No caption or sentence may let the name imply that the interval delivers
   pure ridge push. The domains also carry **colours** in figures (blue / orange, from
   the schematic); those are figure style, recorded in each repo's `FIGURE_STYLE.md`,
   not here — §"Scope" excludes colour from this file.
5. **Banned phrasings:** "net force" where `dN_D = -d\bar\sigma_{zz}` is meant; "walls" of
   a column (use *vertical planes*); free-floating "horizontal forces" without an
   integrated-traction register.
6. **Resultants vs tractions.** Per `trench_pull_fluidity/CLAUDE.md`: all of `N_D`,
   `GPE*`, `V`, `F_B` are *resultants*. A caption must not describe their sign as a
   direction without naming the outward normal of the plane.
7. **Units and significant figures** follow `POLICY_reference_values.md` rule 4. Do not
   restate a number that file governs; cite it.

## 5. Sign and geometry conventions

Carried verbatim from `trench_pull_fluidity/CLAUDE.md`. These are correct and are **not**
up for renegotiation during the symbology sweep — but any rename touching a stress
component must preserve them.

- $x$ rightward positive, $z$ **downward** positive; $z = Y_{\mathrm{SURFACE}} - y$.
- ⚠ **CORRECTED 2026-10-10. Fluidity is NO LONGER MIRRORED.** This bullet read
  "the Fluidity model is mirrored in $x$ at extraction to match the MDOODZ /
  `trench_pull_mdoodz` orientation: subducting plate on the right", which
  `ANALYSIS_CONVENTIONS.md` §1.1 retired on 2026-09-30 — and this file, the
  notation register, went on asserting the opposite for ten days. **Fluidity
  runs in the model's own orientation: subducting plate on the LEFT, seaward
  at $-x$, $v_x > 0$ and $V(x_T) > 0$.** MDOODZ and ASPECT keep the plate on
  the right; the suite has no common polarity and each repo's `MODEL.md`
  declares its own. Nothing a reader sees depends on it: every presented
  horizontal axis is the seaward distance $s = x_T - x$, which is identical in
  either orientation (conventions §1.1, "nothing native reaches the reader").
  The eight fluidity notebooks still call `mirror_fields_in_x` and are a
  declared deviation (conventions §9).
- Off-diagonal stress sign flip $\sigma_{zx}^{z\text{-down}} = -\sigma_{xy}^{y\text{-up}}$
  is applied at extraction, not inside $V$'s formula. (Index order follows D2: `zx` in
  the z-down frame; the y-up component keeps its native $\sigma_{xy}$ name.)
- Diagonal components $\sigma_{xx}, \sigma_{zz}$ are invariant under both the $y\to z$
  flip and an $x$-reflection — no sign change, only `np.flip` for spatial
  reordering. $\tau_{zx}$, $v_x$ and $V$ negate under the reflection; $N_D$,
  $\mathrm{GPE}^*$, $F_B$ and $M$ do not. This is what makes the orientation
  bookkeeping rather than physics, and it is the invariance any future frame
  change must be tested against.
- **Slab frame (D5, ratified 2026-08-20):** $\xi$ slab-parallel, $\eta$ slab-normal,
  $\theta$ the local dip taken from the spline tangent to the SP = 0.5 slab-top contour.
  Rotation into this frame, normal-stress differences written with $\sigma$ per
  POLICY_symbols rule 2 (the isotropic part cancels in every difference):
  $\sigma_{\xi\xi}-\sigma_{\eta\eta} = (\sigma_{xx}-\sigma_{zz})\cos 2\theta + 2\tau_{zx}\sin 2\theta$.
  **⚠ RULED 2026-09-01: the collision resolved against the slab frame.** The register
  confirms $\xi$ = integration dummy (load-bearing in the new $Q(z)$ definition) and
  $\zeta$ = plate-centred coordinate (SI only). The slab-frame pair must migrate; a
  replacement ($s$ down-dip, $n$ slab-normal proposed) is REPORTED upstream (§7) and
  not coined locally. Interim: user-facing figure titles are WORDED ("down-dip
  normal-stress difference"), no $\xi/\eta$ subscripts; in-notebook math may keep
  $\xi/\eta$ with a pending-migration note. `fluidity_slab_normal_FD.ipynb` §12
  awaits the ruling before its internal sweep.
- **Δ operator:** POLICY_symbols fixes $\Delta(\cdot)\equiv(\cdot)(x_I)-(\cdot)(x_T)$.
  The notebooks additionally use an *incremental* form $\Delta f(x)=f(x)-f(x_T)$ (a
  function of $x$); the register has no symbol for it — reported upstream (§7). Until
  ruled on, notebooks must define the incremental form explicitly at first use.

1. Edit this file at the umbrella root.
2. Run `/symbology-audit` from `~/projects/pyvista` to see what the change breaks.
3. Fix the hits repo by repo, on a branch, one repo per commit.
4. Re-run `/symbology-audit` — it must come back clean.
